 6 World Coordinate System
The science dataset must be calibrated to allow conversion of focal plane x, y positions to right ascension and declination. The conversion is dependent on the specifics of the instrument and telescope configuration at the time of the dataset’s acquisition (although many of the parts of the conversion are constant.)
The production of WCS information is done in the instrument software by using values in a structure fetched from the TCS called the TCS Context, a WCS calibration file specific to the instrument, and other information also specific to the instrument. A detailed description of the TCS context and the WCS calibration file is given in Section 4.3 and 4.4, respectively
If an instrument needs more than one focal plane to sky transformation (for example for different wavelengths or chop states) then the WCS should be calculated separately for each case.
6.1 Inputs
There are two sources of inputs for the WCS calculation: telescope systems and instrument.
6.1.1 Telescope System Inputs

6.1.3 Time
In those cases where a time card is available, the time can be retrieved directly from the Gemini Time Bus. Otherwise, the time can be simulated. TAI is a sensible choice and is used in the example on Section 5. Whatever timescale is specified, it is important that it be continuous across a leap second. Suitable alternatives are TT and UT1.
TAI is used to calculate TDB-TT and the equation of the equinoxes in the TIMELIB routines, therefore it does not need to have a high accuracy.

 It is important to note that the WCS routine should be called as close as possible to the start of the observation.

  6.4 WCS Calibration File
used to date)
 Table 6.31: TCS Context
The WCS calibration file is a four column text file containing the measured positions of a star on the chip in pixel coordinates (i,j) and the corresponding position of the star at the focal plane (x,y). The routines in ASTLIB are used to calculate the affine transformation between the two systems of coordinates.
The calibration file name should adhere to the following convention:
<ao><inst>_<port>_<detector|camera|etc..>.wcs
where:
<ao> is “ao” when the AO fold is in use, or empty otherwise
<inst> is the Gemini name of the instrument in lowercase
<port> is the port number where the instrument is installed on
<detector> is the detector number (can be omitted in the case of a a single detector) <camera> is the camera type in case two o more are use in such instruments (can be omitted in the case of a single camera)
